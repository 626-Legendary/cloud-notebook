# 提交前敏感信息检查

本文维护提交前检查方法，不授予推送权限。全局环境与数据限制见 [AGENTS](../AGENTS.md)，安装部署见 [README](../README.md)。

## 每次提交前

- 核对当前分支和已有修改，只暂存本次任务文件，保留用户改动。
- `.gitignore` 和 `.dockerignore` 分别控制 Git 候选与 Docker 上下文，两者都需检查；忽略规则不能自动移除已经跟踪的文件。
- 真实 `.env`、账号、密钥、SSH／包管理器凭据、隧道 Token、数据库、附件、备份和浏览器认证状态不能进入提交。
- 环境模板保留占位值；一次性测试凭据不能复用于真实实例。公开作者署名不等于秘密，应区分处理。
- 模式扫描、已知密钥比对和人工审阅各有局限；不要输出真实密钥来证明扫描成功，也不要把旧扫描当作当前保证。

只读预览：

```bash
git branch --show-current
git status --short
git add --dry-run .
git diff --cached --name-only
git diff --cached --stat
```

检查具体暂存内容时在本地审阅，报告不要粘贴可能含凭据的 diff。不要用 `git add -f` 绕过安全忽略规则；提交范围应使用明确文件列表。未获授权不主动 Push。

若真实凭据已进入历史或远程，先撤销并轮换；仅删除工作区文件不足以消除历史泄露。
