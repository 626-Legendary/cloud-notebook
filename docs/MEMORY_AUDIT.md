# 编辑器空闲性能修复

版本：1.0.1112。日期：2026-11-11。

## 问题与原因

点击正文或输入后，即使停止操作，编辑器仍可能持续产生事务和 React 渲染。修复前的隔离浏览器实验中，仅点击三字符文档、不输入，90 秒约产生 5 万次事务，正文变化和保存请求均为零。问题并非必须由大文档、图片或频繁保存触发。

`PageEditor` 每次渲染重新创建浮动格式工具栏的 `shouldShow` 函数与 `options` 对象。当前 Tiptap React 组件检测到引用变化后发送 `updateOptions` 元数据事务；页面监听所有事务并无条件递增选区 revision，再次渲染并创建新的配置，形成持续循环。

这是已复现的空闲性能缺陷。修复目标是消除持续事务、无效渲染及其分配压力，不将有限时间验证等同于证明所有浏览器、文档和运行时长都不存在其他内存问题。

## 实现

- 浮动工具栏的显示判断和定位选项使用模块级稳定引用。
- 仅在正文、选区或 stored marks 变化时触发工具栏状态同步，纯元数据事务不刷新格式控件；上传选区书签的事务映射继续独立保留。
- 每个编辑器组件实例只初始化一次文档扩展与初始正文解析结果。保存返回的新页面属性不会覆盖活动编辑器正文。
- Workspace 继续通过页面 ID 和显式恢复 revision 管理组件身份。正常保存不重建编辑器；切换页面和显式恢复仍按现有流程加载相应正文。

## 兼容性与发布

不修改数据库 Schema、已发布迁移、正文 JSON、自动保存间隔、页面版本校验、409 冲突语义或同页保存队列。不新增依赖。工具栏仍需正确反映选区及格式，不能简单移除所有事务监听。

包、锁文件根版本、默认显示、环境模板和 Compose 默认／隔离版本为 1.0.1112。真实 `.env` 与其他运行配置未修改；发布时将目标环境的 `APP_VERSION` 设置为 `1.0.1112`，按正常部署流程重新构建。此修改未部署或重启正式服务。

## 验证方式

`tests/e2e/editor-idle.spec.ts` 在一次性 3002/tmpfs 环境创建合成文档：

1. 点击正文后静置，检查事务停止且没有保存请求。
2. 发送纯元数据事务后静置，检查没有工具栏配置更新循环。
3. 验证编辑、加粗、字号、撤销和重做后仍回到空闲状态。
4. 保存后检查正文、格式和编辑器实例保留。
5. 切换页面再返回，检查文档与格式正确恢复。

断言针对空闲期间的事务增量，不使用固定的进程内存上限，以免将浏览器内存分配策略误判为业务回归。长期观察应分别查看回收后的堆、DOM／监听器数量及 CPU，不能只比较进程的一次峰值。

实际执行结果与命令见 `tests/README.md` 和 `CHANGELOG.md` 的 1.0.1112 记录。

## 本次静置测量

隔离生产构建、Chromium，输入一次正文后静置 60 秒，自动保存仍按现有默认间隔执行一次；没有移除或改写编辑器的任何业务回调。观察区间内事务增量为 0，工具栏配置更新事务为 0，主线程 TaskDuration 增量约 0.33 秒。回收后的 JS 已用堆由约 6.60 MiB 到 6.75 MiB，DOM 节点保持 797、监听器保持 739。修复前相同输入后静置实验在 60 秒产生 34,186 次事务，主线程 TaskDuration 增加约 59.70 秒。

结果表明已复现的持续事务与渲染循环被消除；这些数值来自合成短文档和有限时间实验，不作为所有场景内存上限。原始记录位于本地 `test-results/editor-idle-measurement/`。
