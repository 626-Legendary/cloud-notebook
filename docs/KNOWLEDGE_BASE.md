# 知识库与结构化引用

适用版本：1.1.1118。

## 使用入口

侧栏“知识库”进入独立路由 `/app/library` 管理词条，不需要选择笔记本。可新建空正文或长篇词条，按正式名称、别名、正文搜索，按名称／创建／修改时间排序。列表默认打开阅读模态框，“编辑词条”进入共享编辑器；编辑模式可以修改名称、别名和正文。关闭或切换前确认保存；保存失败不会直接丢弃编辑，用户可选择继续处理或明确关闭。

在页面或词条正文中手动输入 `@`，再输入名称或别名。方向键选择、Enter 确认、Esc 保留原文字并关闭联想；也可点击候选项。没有同名目标时，明确选择“创建词条”才创建空词条并插入引用，不强制打开详情。正式名称和别名共享当前账号下的唯一命名空间，统一 NFKC、大小写和空白归一，别名去重。

邮箱、URL、代码块、行内代码和已有链接不触发不合适的联想；粘贴普通 `@文字` 不自动转为引用。已有结构化引用通过编辑器 HTML 剪贴板保留 ID。组合输入状态不确认联想，真实中文输入法仍需按操作系统进行人工验收。

点击页面内引用显示摘要预览，可打开完整词条。在完整模态框里点击其他词条引用直接切换，不叠加多个详情框；最多保留 100 次返回路径，不递归渲染目标正文。默认不提供创建当前词条自身引用的候选项。普通超链接仍独立工作。

## 数据和共享编辑器

新增迁移 `0006_knowledge_and_tags.sql`：

| 表 | 职责 |
| --- | --- |
| knowledge_entries | 当前用户独立词条，Tiptap JSON、名称、并发版本、时间及软删除标记 |
| knowledge_names | 正式名称与别名，共享每用户唯一的 normalized_name；目标通过稳定 entry_id 关联 |
| tags | 初版遗留表；标签功能已移除，不再读写，原数据保留 |
| content_tags | 初版遗留关联表；不再提供分配、筛选、合并等功能 |

词条与页面共用 `PageEditor`、Tiptap 扩展、工具栏、上传、搜索、草稿和保存队列。`resourceType` 仅选择资源接口与上下文控件；没有复制另一套编辑器。词条队列／草稿键使用 `entry:<id>`，避免与页面混淆。正文写入使用对应资源的串行队列，离开前等待完成；保留版本校验及 409，不自动换版本号覆盖。别名单独保存也使用本地已知版本，不能通过预先读取服务器版本绕过冲突。

词条暂不提供页面式历史快照入口；名称、别名更新不重写引用它的其他正文。主动删除词条前提示引用来源数量；删除保留引用节点及其原始 ID／文字，显示失效状态。已删除词条的数据和图片在现有 7 天删除保留期内受保护，之后按已有维护流程物理清理。未引用词条不会因缺少引用被清理。

## 引用契约

```json
{
  "type": "knowledgeReference",
  "attrs": {
    "entryId": "目标词条 UUID",
    "label": "创建引用时的正式名称",
    "referenceType": "entry"
  }
}
```

这是行内原子节点，目标始终为知识库词条，不是页面。词条重命名后，编辑器、阅读界面、摘要和打印按当前用户目录解析正式名称；原始存储 label 用于目标失效时回退，不批量改写历史正文。没有展开目标内容，所以互相引用不会造成渲染或导出递归。

`knowledge-reference` 是客户端、服务端 Schema 和剪贴板共用节点；`knowledge-document` 集中负责引用遍历、ID 映射、展示名称及精确路径替换；`knowledge-trigger` 判断输入上下文；`KnowledgeMentions` 处理手动联想和键盘交互。节点视图订阅在销毁时释放，引用显示文字更新只改变必要 DOM，避免重新引入空闲事务循环。

## 反向引用与检查

反向引用直接从当前已保存、未删除且父笔记本有效的页面及词条正文派生。按来源去重，同一来源多个节点仍可在检查中分别统计。点击页面来源会关闭模态框、打开对应笔记本／页面，再尽力定位第一处目标引用并短暂高亮；定位失败不阻止打开页面。

“账号与设置 → 数据管理 → 引用检查”提供手动扫描和重新构建。没有独立持久化引用索引，因此重建是重新读取真实正文，不改正文、不需要定时扫描，也不存在第二份可失步的引用列表。页面与词条的日常保存天然成为下一次查询的事实来源。

检查显示词条数量、有效／失效引用数、未被引用词条数，以及异常来源、原始文字、节点路径和修复入口。正式名称／别名冲突也会报告。未引用词条和词条间循环关系均不是错误。

修复支持重新关联已有词条、创建新目标并关联、转换为普通文字。每次仅修改所选来源、版本和 JSON 节点路径对应的一处；正文版本或原节点改变时返回 409，要求重新检查。新建目标和正文修复在同一事务中，位置失效不会留下空词条。页面修复前保留快照。

目录仅加载轻量元数据；全文搜索和反向查询按篇读取正文，避免页面为显示引用而一次加载全部知识文章。当前仍是应用层检索，没有全文索引；大量文档的手动扫描耗时取决于正文总量，不宣称已验证无限规模。

## 路由、预览与外链

`/app/library` 与 `/app` 复用 Workspace、会话与权限检查，刷新和浏览器返回保持对应视图；从页面进入前等待编辑保存。侧栏和标题使用 Lucide LibraryBig，导入使用 FileUp。词条仍在单一详情模态框中阅读，不新增词条详情路由。

预览弹层明确使用浅／深色不透明纸张背景、边框与阴影。阅读正文中的普通外链使用 target=_blank 和 rel=noopener noreferrer，新标签页打开，原工作台保留；编辑模式继续保留编辑器对链接的编辑行为。

标签功能已移除，包括界面、API、筛选、关联读写和业务组件。为避免删除已有数据库数据，保留已发布迁移及遗留表；CNF2／用户 ZIP2 的 tags、pageTags、tagIds 字段作为文件兼容字段保留，新导出为空数组，旧文件中的标签不再恢复。整库在线备份仍原样保存数据库。

## API 边界

- `GET/POST /api/knowledge`：列表／检索及创建；`catalog=1` 返回用于引用展示的轻量目录。
- `GET/PATCH/DELETE /api/knowledge/[id]`：读取、带 version 更新及软删除。GET 返回 `{ entry, backlinks }`；PATCH 沿用共享编辑器的 `{ page }` 保存包装。
- `POST /api/knowledge/check`：手动派生检查；`POST /api/knowledge/repair`：带版本与路径修复。
- 所有接口核验会话、普通用户角色、账号归属及来源；页面同时检查父笔记本有效性。写入沿用缺少 Origin 时允许的现有约定，错误为 `{ error }`，冲突附当前版本或现有目标 ID。

## 导出、迁移与回滚

CNF2 支持单页面、笔记本和完整知识库，规则见 [CNF_FORMAT.md](CNF_FORMAT.md)。管理员用户 ZIP 新导出为格式 2，包含词条和新旧 ID 映射。CNF 与管理员用户 ZIP 恢复共用 knowledge-import 命名空间计划器，冲突返回 409 和 conflicts 清单；界面提供取消、复用已有词条、保留双方并重命名三种选择。复用保留目标正文与别名，导入引用映射到已有 ID；重命名为冲突名称／别名添加“（导入 N）”，导入引用映射到新 ID。多个目标占用同一导入词条的名称时禁用复用，可选择重命名。写入事务内重新检查命名空间，失败回滚本次数据和文件。原用户 ZIP 格式 1 的恢复行为保留；这不是旧 CNF 兼容分支。系统在线数据库备份自然包含新表和受保护的附件。

迁移只新增表、索引和删除触发器，不清空、不重写原有笔记本、页面、版本或正文。上线前使用现有 SQLite 在线备份和附件归档；不要复制正在写入的主数据库文件当作完整备份。回滚到旧应用前应恢复升级前的完整备份，避免旧编辑器打开新引用节点后丢失不认识的结构；不要通过修改旧迁移或手工删表回滚。

本次验证只对隔离数据库和一次性容器执行；真实 `.env`、运行数据库及正式服务未修改。部署时将目标 `APP_VERSION` 设置为 `1.1.1118`，按常规构建／迁移流程升级。浏览器和集成验证范围见 [测试说明](../tests/README.md)。
